# Check a request in Lumen

Lumen's search results are a separate view of equipment requests, not a live reading of each stored record. Creating or editing a request changes the stored record first; search normally catches up within two minutes. A backlog can take longer, and there is no guaranteed maximum delay.

To check current values, open the request link. If you only have its stable request number, use Open by number. Both read the stored record subject to your permissions. When the page opens, its values and status are authoritative for that request at the time it loaded; another edit can happen later.

## What a search result can tell you

A result tells you what the search view contains. An edited request can still show old values there. Refreshing the browser reruns the search against that same possibly stale view; it does not force an update. Lumen has no user control for forcing one.

A missing result does not establish that the request was deleted. Search defaults to open requests, so a closed request can be absent even though its record still exists. Selecting Include closed changes the filter, but cannot fix a stale search view. A newly created request can also be missing while search catches up. Open the link or use Open by number to check the record you are allowed to see.

Deletion has the opposite effect: an old search result can remain temporarily after the stored record is removed. Opening it shows `Request not found`. That message can also mean you lack permission, so it does not prove deletion. Having the request number does not prove access either.

## When to ask the service desk

If the request page and search still disagree after the usual two-minute interval, send the service desk the request number and the times you observed the discrepancy. Do not send private request contents. The service desk checks backlog and access; team leads cannot diagnose the backlog or restore deleted records. There is no published recovery time.
