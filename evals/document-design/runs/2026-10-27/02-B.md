# What Lumen search tells you

Lumen search shows a separate search view of equipment requests. A request page reads the current stored record. Changes reach the stored record first, so search can lag behind a creation, edit, closure, or deletion.

Search normally catches up within two minutes, but a backlog can take longer; two minutes is not a guaranteed limit. Refreshing your browser reruns the search against the same possibly stale view. There is no user control to force an update.

A missing result does not prove deletion. Search defaults to open requests, so a closed request may be hidden. Select **Include closed** to include closed requests, but remember that this changes the filter without updating the search view. Closing a request changes its status to Closed; it does not delete it.

An existing result does not prove the record still exists or that its displayed values are current. After deletion, an old result can remain temporarily. Opening it may show `Request not found`. That message can also mean you lack permission; the screen does not distinguish the reasons. A request number alone does not prove access.

To check a request, open its link or use **Open by number** with its stable request number. Both read the stored record subject to your permissions. If the page opens, its status is authoritative for that request when the page loads. Another edit can occur afterward.

If search and the record page still disagree after the usual two-minute interval, send the request number and the times you observed the disagreement to the service desk. Do not send private request contents. The service desk checks backlog and access; team leads cannot diagnose the backlog or restore deleted records. There is no published recovery time.
